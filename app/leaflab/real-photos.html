How to use actual images in LeafLab

  1. Choose Original JPEG on a photo card. Save the exact original file, not a screenshot or the resized gallery preview. That preserves the published file's byte identity.
  2. Open Specimen Provenance v1.3, select the saved original, and record its SHA-256 plus the capture metadata known from the Commons page. Mark unknown fields as unknown. Source license is not proof of botanical classification.
  3. Open Human Vein Reference v0.7 and make independent annotations on the same saved original file. Use different masked observer codes. Do not show model predictions to observers intended to be blind.
  4. Use Evidence Gateway v1.2 for same-image agreement, plant-ID separation and descriptive development/holdout audits. Do not put two potentially related images in different splits unless independence is documented.

For command-line acquisition, run npm run fetch:leaflab-photos. The script downloads the original Commons JPEG bytes, checks source-listed byte counts and SHA-1, computes a fresh SHA-256 for each file, and writes a manifest plus license credits to an ignored local directory. The GitHub Actions photo-pack workflow can package the originals as a downloadable artifact when network access permits.

No verified real-world accuracy numbers are bundled. The software tests validate the catalog and download guards, not botanical truth. New photographs may have shadows, overlapping leaves, text overlays or capture variability that defeat our existing detector.

This catalog page loads photo previews from Wikimedia Commons, which receives normal web image requests. Downloading originals opens Wikimedia's file server. Specimen analysis in the linked LeafLab tools remains browser-local; no uploaded dataset or remote inference is performed.
